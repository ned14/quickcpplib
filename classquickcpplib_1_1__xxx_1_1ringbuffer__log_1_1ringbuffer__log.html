Detailed Description

template<class Policy, class LogLevelChecker>
class quickcpplib::_xxx::ringbuffer_log::ringbuffer_log< Policy, LogLevelChecker >

Very fast threadsafe ring buffer log.

Works on the basis of an always incrementing atomic<size_t> which writes into the ring buffer at modulus of the ring buffer size. Items stored per log entry are defined by the Policy class' value_type. To log an item, call the QUICKCPPLIB_RINGBUFFERLOG_ITEM_* family of macros.

Be aware iteration, indexing etc. is most recent first, so log[0] is the most recently logged item. Use the reversed iterators if you don't want this.

Logging is wait-free and never locks: a writer allocates its record id with one atomic fetch_add on the counter, marks its slot with the per slot seqlock word, writes the record and marks the slot clean again. Nothing waits on anything else, so a writer cannot be delayed by a slow or descheduled peer. This is a write-heavy, read-light log, and the protocol is arranged accordingly: the writer allocates one id, stores two marker words and copies the record, with the cheapest fences which are sufficient; a reader which races a writer re-checks and retries, and a reader which cannot get a whole record gives up rather than making the writer wait. Anything which makes writing slower to make reading cheaper or tidier is the wrong trade here.

A record is published in the sense that matters to a reader when its slot holds it, not when its id was allocated: two writers can be mid-flight at once, and one may finish before the other, so an id below the counter is not a promise that the record is there yet. Readers therefore validate what they copy - the seqlock word must be even at both ends of the copy, and the copy must carry the id which was asked for - and give up after a bounded number of attempts, returning a default constructed record. This is what makes the tear-free accessors safe without a lock: a slot holding a previous wrap's record, or an id whose writer has not finished, fails the id check rather than being returned as data.

One precondition follows from the same reasoning, and it is the only one: no more writers may be inside a push at the same time than the ring has entries (max_items), because two writers whose ids differ by exactly the ring size share a slot and would interleave their seqlock updates. Threads which log into their own log (the usual arrangement) satisfy it trivially; a shared log needs fewer concurrent writers than it has entries, which for the default 256 entry debug ring is almost always true. clear() additionally assumes no writer is inside a push: it rewrites every slot, and a writer interleaving with that is a different question from the one seqlocks answer.

For simple_ringbuffer_log_policy, typical item logging times are:

  • without backtrace: 1.2 microseconds.

  • with backtrace (windows): up to 33 microseconds.

void quickcpplib::_xxx::ringbuffer_log::ringbuffer_log< Policy, LogLevelChecker >::swap ( ringbuffer_log< Policy, LogLevelChecker > & o)
inlinenoexcept

Swaps with another instance.

No synchronisation, and none is possible: this exchanges what each slot means for both logs at once - the records, the counter which numbers them, the markers which say which record is in which slot, and the point a clear retired ids at. A writer or reader running concurrently would be observing a log whose identity changes underneath it mid-operation, and there is no ordering which makes that observation meaningful; the requirement is exclusive access to both logs, exactly as std::swap on any container which is not itself thread-safe. The relaxed marker exchange below is the consequence, not an oversight: nothing is being published to anyone, because nobody else may be looking.

The atomics are exchanged element-wise because a vector of atomics cannot be swapped as a whole and because the marker words belong with the records they describe - they are moved together with _store and _counter. The bounds check is defensive: the parameter type fixes the container type, so two logs of this instantiation always have the same slot count.

(As the open-work register records, this function cannot currently be instantiated at all: std::swap does not accept the atomic members.)

Returns a tear-free copy of the record pos items from the newest, or a default constructed record if the ring does not hold that many. pos counts from the newest exactly as operator[](size_type) does. The accessors which hand back a reference into the ring (front(), back(), operator[], at() and the iterators) are racy by construction: a writer which wraps the ring can rewrite the very slot a reader is looking at, and no ordering prevents that. This copies the record out and discards the copy if the writer got to the slot first, so what it returns is always one whole record.

template<class Policy, class LogLevelChecker>
void quickcpplib::_xxx::ringbuffer_log::ringbuffer_log< Policy, LogLevelChecker >::clear ( )
inlinenoexcept

Clears the log.

Rewrites every slot and retires every id issued so far.

Takes no lock and cannot take one without reintroducing the serialisation the class documentation rules out, so it assumes no writer is inside a push: a writer interleaving with the loop below shares a slot with it and the two would interleave their seqlock updates. Clearing a log concurrently with logging into it is a teardown/reset operation, not a logging operation; the per-slot marking is still worth doing, because it stops a reader accepting a slot mid-clear as a record, which is a different race and one this can close.

1251 {
1252 // Clearing rewrites every slot, so it takes the same dirty/clean marking a
1253 // writer does: without it a reader could accept a slot mid-clear as a
1254 // record, exactly as it could mid-write.
1255 for(size_type i = 0; i < _store.size(); i++)
1256 {
1257 const size_type idx = i % _slots();
1258 // A marker no record can produce: 0 is neither `_seq_dirty(id)` nor
1259 // `_seq_clean(id)` for any id (those are 1 and 2 at the smallest), so a
1260 // reader rejects the slot instead of copying a cleared one.
1261 _seq[idx].store(0, std::memory_order_relaxed);
1262 std::atomic_thread_fence(std::memory_order_release);
1263 _store[i] = value_type();
1264 }
1265 // Retire everything pushed so far rather than resetting the counter: a
1266 // reset made ids issued before the clear name whatever record now occupies
1267 // that slot, i.e. silently resolve to someone else's data.
1268 _cleared_at.store(_counter.load(std::memory_order_acquire), std::memory_order_release);
1269 }
