Detailed Description

template<class Policy, class LogLevelChecker>
class quickcpplib::_xxx::ringbuffer_log::ringbuffer_log< Policy, LogLevelChecker >

Very fast threadsafe ring buffer log.

Works on the basis of an always incrementing atomic<size_t> which writes into the ring buffer at modulus of the ring buffer size. Items stored per log entry are defined by the Policy class' value_type. To log an item, call the QUICKCPPLIB_RINGBUFFERLOG_ITEM_* family of macros.

Be aware iteration, indexing etc. is most recent first, so log[0] is the most recently logged item. Use the reversed iterators if you don't want this.

For simple_ringbuffer_log_policy, typical item logging times are:

  • without backtrace: 1.2 microseconds.

  • with backtrace (windows): up to 33 microseconds.

inlinenoexcept

Returns a tear-free copy of the record pos items from the newest, or a default constructed record if the ring does not hold that many. pos counts from the newest exactly as operator[](size_type) does. The accessors which hand back a reference into the ring (front(), back(), operator[], at() and the iterators) are racy by construction: a writer which wraps the ring can rewrite the very slot a reader is looking at, and no ordering prevents that. This copies the record out and discards the copy if the writer got to the slot first, so what it returns is always one whole record.

957 value_type ret;
958 // The ring holds at most `held` records, so a request from beyond that can
959 // never be satisfied. Asking _try_snapshot_counter for it used to loop
960 // forever: the counter-based liveness test rejects exactly pos >= held, so
961 // snapshot(size()) - and snapshot(size()-1) once the ring had wrapped -
962 // spun with no escape, in a const noexcept accessor documented as
963 // returning a default constructed record in that case. The attempt bound
964 // covers the other end: a writer that keeps overwriting the requested slot
965 // must make the reader give up, not livelock.

◆ _seq

template<class Policy, class LogLevelChecker>
std::vector<std::atomic<uint32_t> > quickcpplib::_xxx::ringbuffer_log::ringbuffer_log< Policy, LogLevelChecker >::_seq
protected

One sequence word per slot: the standard seqlock protocol, and the reason the snapshot accessors can copy a record while a writer runs. The writer bumps the word to ODD before touching the slot and to the next EVEN value after, so a reader that sees an odd word, or a word that changed across its copy, knows the copy is not a record and discards it. Without this the copy was an ordinary read racing an ordinary write: only the counter was atomic, so "detect and discard" was value-based reasoning about a data race that the memory model does not sanction, however many stress runs failed to see it.

◆ _cleared_at

template<class Policy, class LogLevelChecker>
std::atomic<size_type> quickcpplib::_xxx::ringbuffer_log::ringbuffer_log< Policy, LogLevelChecker >::_cleared_at
protected

The counter value at which the log was last cleared. The counter keeps counting across a clear - deliberately: it is the identity of a record, and resetting it made every id issued before the clear valid again, naming a DIFFERENT live record. Records pushed before _cleared_at are simply not live any more, so an old id resolves to nothing instead of to someone else's data.
